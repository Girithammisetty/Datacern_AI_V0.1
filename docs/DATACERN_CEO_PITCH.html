The seam

Every healthcare call that matters ends in a case. A prior auth to adjudicate. An appeal to review. A denial to work.

Today that case falls off the end of a voice platform into a human queue — no governance, no evidence trail, no learning loop. The conversation is automated. The decision behind it is exactly as expensive as it was before.

Your product stops when the call ends. This one starts there.

The two halves don't overlap. There is no telephony anywhere in this platform, deliberately. The integration seam is a webhook: your agent finishes a call and posts the outcome, and a governed case exists on the other side.

How it works

The AI drafts. A named human signs. The correction teaches the next one.

It isn't AI that decides. It's AI decisions that can be audited — evidence, proposer, approver, effect, on a tamper-evident record. Three things make that real rather than aspirational:

  • Self-approval is rejected by the server. Not a UI convention. The proposer cannot be the approver, and high-risk, destructive or admin actions require a second, distinct human with no tenant opt-out.
  • A pack refuses to install against a tenant with no real data, naming every missing field. The platform will not half-work to make a demo look good.
  • Budget caps fail closed — platform, tenant, workspace, principal, key. When the ceiling is reached, it stops.

Integration

Standard MCP, inbound, today

The platform is an MCP server: one JSON-RPC endpoint, spec version 2025-06-18, with initialize, tools/list and tools/call. All nine agents route their tool calls through that single chokepoint, and a backend is only reached once every gate has passed.

Your voice agent can drive it as a standard MCP client. Every call is authorised, tiered, kill-switchable and audited.

The limit, stated plainly: outbound federation uses our own facade contract, not MCP — so this platform cannot consume a third-party MCP server today. That is an adapter behind an existing interface, and it is not yet built.
